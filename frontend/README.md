# WindBlick – frontend

Vue 3 + TypeScript + Vite implementation of the WindBlick Figma prototype
("windblick prototype" file in Figma), wired to the API contract in
`docs/api-contract.md` (v0.1 draft).

> **Status: prototype for team discussion.** It deviates from `AGENTS.md` in
> two ways that need a team decision: it uses TypeScript, and while no backend
> endpoint exists it renders previews with a browser-side **mock** of the
> backend (`src/api/mocks/`), which must be removed once the backend renders.

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # type-check + production build
```

## Flow

| Route      | Screen          | Main pieces                                                         |
|------------|-----------------|---------------------------------------------------------------------|
| `/`        | 1. Select photo | `views/UploadView.vue` (JPEG/PNG ≤ 20 MB, uploaded unchanged)       |
| `/check`   | 2. Check photo  | `components/check/*`: map (camera + NRW turbine selection), camera overrides, selected turbines |
| `/preview` | 3. View preview | `components/preview/CompareSlider.vue`: original vs. backend-rendered PNG |
| —          | Intro pop-up    | `components/intro/*`                                                |

Shared state lives in `stores/session.ts` (Pinia).

## API contract mapping

| Contract                                   | Frontend                                                   |
|--------------------------------------------|------------------------------------------------------------|
| `POST /api/v0/visualizations` (multipart)  | `api/visualizations.ts` → `createVisualization()`          |
| Request/response/problem types             | `types/contract.ts` (snake_case, as on the wire)           |
| `parameters` JSON                          | `stores/session.ts` → `buildParameters()`                  |
| Camera overrides vs. EXIF                  | Empty form field ⇒ field omitted ⇒ backend uses EXIF       |
| Field errors (`errors[].path`)             | Shown next to the matching input; others in a banner       |
| Turbines = normalized NRW WFS records      | `api/turbineSource.ts` (selection only, dimensions read-only) |

- Requests generated by `buildParameters()` validate against
  `docs/api/visualization-request.schema.json`.
- Browser-side EXIF reading (`lib/exif.ts`) is only a *preview* for
  placeholders and the map; those values are never sent as overrides.
- In development Vite proxies `/api` to `VITE_BACKEND_URL`
  (default `http://localhost:8000`), so no CORS setup is needed.

### Mock mode (`VITE_USE_MOCKS=true`, default)

`api/mocks/mockBackend.ts` emulates the endpoint in the browser: validation,
field-level override/EXIF merge, `CAMERA_PARAMETERS_UNRESOLVED`, turbine
outcomes, warnings and `camera_value_sources`. Its EXIF support is narrow on
purpose: only GPS lat/lon and a true-north image direction; elevation, pitch,
roll and field of view must be entered. Set `VITE_USE_MOCKS=false` to call the
real backend once the endpoint exists.

## Open points for the team

- **Turbine source:** the real NRW WFS adapter (GetFeature, CRS/axis order,
  string parsing) is not implemented; `api/mocks/wfsFixture.ts` provides
  clearly labelled demo records. The WFS has **no base elevation**, which the
  contract requires — where should it come from (backend DGM lookup?).
- **Design vs. contract:** Figma shows free turbine placement and editable
  hub height / rotor diameter; the contract only accepts WFS records with their
  own dimensions. The UI follows the contract.
- **Camera values:** EXIF rarely provides elevation (with known datum), pitch,
  roll or usable intrinsics, so users will usually have to enter these.
- TypeScript vs. plain JS (AGENTS.md), and convergence with PR #50.
